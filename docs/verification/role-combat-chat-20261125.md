# 对局聊天实现记录

对局和训练中的个人战斗 HUD 先计算血蓝、技能、充能、控制和角色状态的实际绘制边界，再布置聊天。默认从 HUD 上缘向上放置输入框和消息，空间不足时沿屏幕可用区域回退。聊天避开个人战斗 HUD、原版快捷栏和准星，优先避开小地图。聊天打开、关闭和滚动都不会改变个人战斗 HUD 的布局。大厅、观战、隐藏 HUD 或没有有效个人战斗快照时，聊天恢复原版位置、输入框和消息样式。

Minecraft 26.3 的原版消息历史、绘制和可点击文本捕获使用同一坐标变换。默认玩家频道在展示时按玩家名和正文分段换行，续行使用正文的起始坐标。队伍、私聊和其他频道保留服务端提供的聊天组件。原版聊天记录、签名、权限、过滤、静音、角标、延迟队列和报告流程仍使用接收到的原始消息。输入框沿用原版编辑框，命令建议和错误提示从实际输入框上缘展开，保留原有补全和键鼠事件。

签名可用且未超过原版客户端有效期时显示签名发送时间。其他玩家消息显示首次接收时间，原版延迟队列中的合法玩家消息和伪装消息采用进入队列前的接收时间。时间随原版历史条目保留，在原版清空历史或删除条目时一并移除。对局样式下用本地时区显示 24 小时制时间，可在聊天打开时悬停查看包括日期、秒数和偏移量的完整时间及来源。窄列会缩短时间或在玩家名尾部显示省略号，为多行正文留出空间。

聊天输入纹理为 `192×72` 的 RGBA 图集，含两个 `192×32` 的状态和中间八像素透明区。两端六像素固定宽度，中段拉伸。资源缺失时使用程序绘制的底色和边框。时间使用六像素高的单独字形，续行缩进按正文起始像素计算。

## 验证

- 用项目实际 Minecraft 26.3 字节码查证原版坐标、建议框、消息接收和签名接口，在 Java 25 上编译聊天实现。
- `CombatChatChecks` 独立执行通过 35 项断言，覆盖 960×540、427×240、320×240、320×180 的 GUI 逻辑像素，包含充能及状态撑高、顶部回退、鼠标及输入坐标、排队提示预留、无个人 HUD、零聊天缩放和跨时区格式。加载该组检查的 `myriad:training_ui` 完成 1 项 GameTest 并通过。
- 通过文件头和系统图像元数据核对输入纹理尺寸及 Alpha 通道。上述结果提供编译、几何、格式和资源证据。真实输入与视觉结果以客户端验收记录为准。
