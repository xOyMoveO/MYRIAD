# #44 本地 GameTest 与同服原生检查

2026-11-17；Fabric 26.3 / Fabric API 0.166.2+26.3 / Java 25。只检查新建合成世界，不读取、导入或代验原始地图。本记录区分历史结果、定向诊断和最终同一 dedicated JVM 的原生 `/test` 结果；不把单次复跑成功当作历史偶发根因已修复。

## 范围与源码

本次永久改动只在 `src/gametest`：

- `CombatRegressionTests` 保留“邻近敌人必须被索敌”的原谓词，把相遇点设置到随机选中单位所属的兵线；保留阵营、存活、实体类型、脱战和逃离目标等检查。
- 水晶结束检查保留胜负断言，随后由 `GameManager.tick` 消费正常的延迟返回大厅流程，新增完成清理断言。不会让待清理状态延后到下一项检查。
- `WorldTimeChecks`、`KehengChecks`、`HeroActionTimeChecks` 的服务器事件观察保持原全部断言、数值和超时；成功时通过 `runAfterDelay(1, helper::succeed)` 回到 GameTest 框架 tick，产生原生完成通知。

没有生产源码、网络协议、技能时序、伤害、范围、地图或玩法语义变更。Flame/Night 的临时调度日志及兵线定向扰动未保留在测试源码中。没有删除或放松有效断言。

## 已复现的夹具原因

### 战斗 tick 28

[原始失败](evidence/same44-combat-original.txt)为 `Minion must acquire a nearby enemy on tick 28`。该夹具从按 UUID 组织的 map 中取任一己方单位，却一律将其放到上路相遇点；选到下路时，该点恰好离它自己的路径十格。`tickMinion` 先执行单位分离，再检查离路线是否超过十格，越界则回道并提前返回，尚未进入索敌扫描。

定向诊断在旧相遇点强制选择下路并布置一个相邻单位，得到[确定性失败](evidence/same44-minion-probe-before.txt)：敌人 `alive=true`、`visible=true`、实体查询包含敌人，但 `nextScan=0`；源单位距其路径 10.1 格。随后保持同一扰动，只把相遇点移回其所属兵线，[定向检查通过](evidence/same44-minion-probe-fixed.txt)。[临时 probe 差异](evidence/same44-probe-source.patch)只作为诊断证据。

这证明原 fixture 的空间前提不成立，无需改变生产回道或索敌规则。原始偶发失败日志没有记录所选 lane，因此不声称能还原那次随机 UUID 的确切单位。

### 同服状态污染

[原生同服修正前日志](evidence/same44-native-before.txt)：`combat_regression` 于 10:06:39 通过，随后 `first_group` 于 10:07:14 在 tick 1 报 Heaven Sword 仍应蓄力失败。

水晶被销毁后，生产流程设置 `returnToLobbyPending=true`。旧 fixture 只通过反射改回 `WAITING`，随即关闭模组；正常服务端 tick 只在模组开启时调用 `GameManager.tick`，因此待处理清理保留。下一检查开启模组后，延迟清理把它刚创建的 runtime 一并清空。定向记录确认 `pendingAfterCrystal=true`。修正后消费该正常流程，并断言 `WAITING` 且 pending 为 false；[同一 dedicated 的 combat→first_group 随后完整通过](evidence/same44-native-diagnostic.txt)（10:14:02 / 10:14:27）。

这条链路只解释本轮已复现的同服 tick 1 失败，不能自动解释独立 JVM 的历史 Heaven Sword 或 Night Blink 失败。

### 框架完成通知

上述诊断同服中，`world_time` 和 `keheng` 记录了自身全部断言 PASS，却没有原生 `Game Test complete` 通知。`GameTestInfo.tick` 会在入口直接跳过已 done 的检查；在外部服务器事件调用 `succeed`，绕过了该 tick 内的 `testPassed` 通知。三处终结现回到框架 tick；最终原生结果另列下方。

## 未归因的历史偶发

- Night Blink 的历史 GitHub run `43893422732` 在 `NightExecutionChecks:59` 的 16 tick 到达断言失败。历史本地两次诊断（含旧 CI 坐标）及本轮 diagnostic 同服均通过，未获得该失败的确定性根因；没有改技能或放松 16 tick 断言。
- 另一个历史 run `43897661893` 为不同的 Heaven Sword 首败，不能与上述 Night 或本轮同服污染合并解释。[历史摘录](evidence/same44-historical-night-heaven.txt)保留其独立性。
- [此前 first_group 本地失败](evidence/same44-first-group-original.txt)为 Flame `No early damage hp=932.5 on tick 17`。本轮临时日志观察到一个 `runAfterDelay(3)` 回调比预定真实世界时间晚一 tick，但没有复现该两 tick 的提前伤害断言失败，故只记录调度限制，不认定其根因已修。

## 原生环境前置与最终同服记录

原生 `/test run` 按 heightmap 选地表高度。无平台的合成平地将模板放在 Y=-60，而部分夹具专为 26.3 headless 的 Y=4 基准设置了负相对高度。第一次 native `yike` 因底部场景超出 -64 最低建造高度，在 tick 2 拒绝 W；这是运行环境前提失配，保留在 diagnostic 原始日志中。

最终运行先在各起点 force-load 区块，再于 Y=3 放置小型合成基准平台，让原生命令实际报告模板坐标 Y=4。[平台预检](evidence/same44-platform-preflight.txt)实际记录 `[20000, 4, 0]`，没有修改任何技能断言或原始地图。

本轮同服由平台预检结束后的**单一 dedicated JVM**执行，端口 `127.0.0.1:25646`。每项原生 `/test run` 串行执行一次，起点从 X=30000 起每项间隔1000格，均由 Y=3 基准平台支撑。结果与隔离专项分别统计；[完整日志](evidence/same44-native-final.txt)、[逐项 JSON](evidence/same44-native-results.json)保留实际记录。

用户随后明确“基础和核心的功能没问题就行了，不要检查得太细节”，因此停止额外全套复跑、历史偶发与逐帧定位；没有重试来筛选全绿。Heaven tick 30和本次聚合伤害异常尚未区分为生产问题还是测试夹具问题，不能声称仅夹具异常，也没有据此认定普通玩家流程存在可复现的核心故障。临时调度日志和定向源码探针均已撤回，隔离服务端已退出。
