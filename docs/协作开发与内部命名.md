## 构建与运行

当前对局阵营为守护（蓝色，`guardian`，网络编号1）和毁灭（红色，`destruction`，网络编号2），双方共享角色池。枚举、同步字段、命令补全、训练请求及玩家界面使用新名称；历史阵营字符串和旧枚举保存值仅在兼容读取入口接收。新增地图/玩家数据/检查点写入新ID，读取旧检查点时同时转换积分字段和已摧毁防御塔键；不直接改写原地图或历史文档。联机客户端、服务端应一起更新，不能以编号未变推断旧客户端界面也兼容。

当前仅维护 Minecraft **26.3**、Fabric Loader **0.20.1**、Fabric API **0.166.2+26.3**、Loom **1.18.4**、Java **25**，Gradle Wrapper 为 **9.7.0**。推荐安装 JDK 25，再用 IDE 打开仓库根目录，导入 Gradle 工程。

Windows PowerShell，在仓库根目录执行：

```powershell
java -version
.\gradlew.bat build
.\gradlew.bat runClient
```

产物在 `build/libs/`。Linux/macOS 使用 `bash ./gradlew build`。首次构建需联网下载 Gradle、Fabric 和 Minecraft 依赖；没有缓存时不要加 `--offline`。Java 工具链解析可能为辅助任务另行下载所需 JDK。

本轮迁移按用户2026-11-17决定聚焦基础核心，性能与细节专项暂缓；最终状态和已知异常见[核心交付](fabric/final44-20261117.md)。以下为后续任务按需选用的专项入口，不追加本轮验收要求：

```powershell
.\gradlew.bat runGameTestServer -PmyriadGameTests -PgameTestFilter=myriad:first_group
```

提交前也可执行 `python tools/check_namespace.py --jar build/libs/myriad-0.1.0.jar`，检查源码命名空间、JSON 和发行包中的旧标识残留。2026-11-12 此项审计、构建和两轮新版角色聚合专项已通过；尚未进行迁移后的客户端画面和旧世界迁移验收。

测试报告在 `build/reports/fabric-gametest.xml`，后续运行会覆盖。角色A/B、刻衡、伊珂、铆钉、角色/战场缓时及合成地图入口见[Fabric开发与复现](fabric/README.md)。旧专项有共同状态，每项独立JVM串行运行；同时核对实际匹配、完成、通过标记与XML，不能只看Gradle退出码。CI按当前用户要求只执行`build`，专项在本地运行。

正式/原始地图及其副本、3v3/5v5实图整局全部由人操作验收。技术侧使用从零生成的[合成地图fixture](fabric/arena-fixture.md)，覆盖点位读写、设施、模式隔离和新检查点；真实双客户端与fixture玩家分别记录。全部视觉、音效听感、手感、流畅性与平衡结论由人给出；自动检查与截图不能代签。

以下路径相对 `src/main/java/com/myriad/`：

技能定义资源位于 `src/main/resources/data/myriad/role_rework/`，含 `first_group.json`、`second_group.json`、`shuo.json`、`keheng.json`、`yike.json`、`rivet.json`。修改简介时同时核对实际技能类与客户端浮窗，而不是只改 JSON。

`FirstGroupSkills` 是历史类名，当前正式登记并可选十四名角色、112 个独立候选技能。不要按类名误判它只管理五个人。十名退役角色的登记、专属实现、武器、网络与发行资产已删除；保留角色自身的历史基础定义仍用于既有共用行为，旧技能类存在不代表当前选角实际调用它。刻衡、伊珂已进入正式选角、对局角色池和图鉴，不再要求训练模式；在新测试世界仍可通过 `/myriad char keheng`、`/myriad char yike` 选择。全部视角、握持、模型、VFX 与听感由人验收，自动化只给客观技术结果。

铆钉使用 `rivet.json` 的八个候选与 `character/skills/rivet/` 的独立技能。基础 W 在零投入时可用，保存的 W 等级仅代表 0～5 次付费强化；不预发等级或占用开局点数。全员选完即传送泉水并关闭选角，原有十秒准备仍保持 `PICKING`，仅铆钉 W 免费可用，开战不重置已布锚点。

公共施法保留三参数 `AbilityRuntime.request` 的既有即时提交语义；四参数入口可声明待提交起手，在实际提交时再次核对资源、分支与落点。`Cast` 提供阶段、一次性提交与取消，`ActionTime` 按对象及来源聚合最小倍率、保留已完成进度。普通 `later/repeat/whileActive` 沿用真实时间；可缓时行动显式使用 `windup/actionLater/actionWhile/actionDash/actionLeap/actionProjectile/actionProjectileAlong`。四法师普攻另经 `MagicBullet` 的私有恢复和独立飞行路径接入。十一人的逐技能适用项、私有攻击帧与真实时间边界见 [角色兼容矩阵](verification/roster13-hero-time28.md)。

兵线、普通野怪的私有 AI 自主步长和攻击恢复使用局部进度；大型首领免缓时但仍承受合法伤害。原版普通／药／光灵箭保留完整位移、重力、阻力及原版碰撞伤害链，当前倍率通过 Fabric 同步 attachment 发送。原版没有固定飞行寿命或射程阈值；本次在玩法启用时新增1200行动tick／2400真实tick飞行清理上限，扎地仍为原版1200tick。三叉戟和第三方任意弹体不纳入。详细实际证据见 [战场兼容记录](verification/roster13-world-time28.md)。

公共机制与删除基线见 [#10 整合验证](verification/roster13-foundation10.md)；两名新角色的伤害、资源、被动、遮挡和生命周期原始证据见 [两角色整合验证](verification/roster13-characters.md)。最终正式十三人、实际同步与统一构建结果见 [#28 整合验证](verification/roster13-final28.md)。这些自动化结果不代表客户端视觉、听感或平衡验收。

## 协作边界

- 服务端权威处理伤害、蓝耗、CD、目标合法性和 motion；客户端输入、HUD 与特效不能替代服务端校验。
- 每角色、每技能独立实现，共用层提供基础能力；不要把具体机制堆到批次注册器里。
- 新版力量用于普攻，智慧用于技能强度。符石系统已删除，旧存档清理不能误恢复系统。
- 历史全局动作系统已移除；当前部分角色的第一人称手臂/武器是独立实现，不要为修持刀恢复整套旧动作系统。
- 新版技能分支与旧技能结构并存，先追踪实际绑定再修改；避免只改未使用的历史类。
- 每次玩法、平衡、界面或视觉更新写玩家看得懂的更新日志，并说明构建、安装、专项验证与实机验收的区别。
- 原作者 `AGENTS.md` 中的本机安装路径只适用于原作者机器，其他开发者不得照搬覆盖自己的正式游戏。
- 建议每项修改建独立分支，提交源码和必要资源，不提交 `.gradle`、`build`、`run*`、游戏存档、令牌或账号信息。
