# Domain Docs

本仓库采用 single-context 布局，约定路径均相对仓库根目录。

## 阅读顺序

探索代码、讨论领域术语或提出设计决策前：

1. 阅读 `docs/协作开发与内部命名.md`，了解现有名称、协作边界和源码入口。
2. 若根目录 `GLOSSARY.md` 存在，阅读其中的领域术语。
3. 若 `docs/adr/` 存在，阅读与本次工作相关的架构决策记录。

术语表或 ADR 尚不存在时，直接继续工作。由 `domain-modeling` 在术语或决策明确后按需创建，无须预建空文件。

## 文件布局

- `GLOSSARY.md`：整个项目共用的领域术语表。
- `docs/adr/NNNN-<主题>.md`：按四位序号记录架构决策。

## 使用规则

- 任务标题、设计提案、假设、测试名称等涉及领域概念时，使用术语表中确定的名称。
- 遇到术语缺口，先核对项目现有用语；确有新概念时，通过 `domain-modeling` 明确后记录。
- 方案与现有 ADR 冲突时，明确指出冲突记录、原因和需要重新讨论的决定。
