# 天刑、素岚与焚诀首轮数值对照

使用樱隙前线 3v3 的 `CHERRY_V2` 规则。改前配对构建为 #111 的 `b368acd`。角色的基础属性、1 至 20 级成长、普攻及 24 个候选技能取自配对构建。原先的伤害、资源和成长采用现值。新增的快照字段补录作用条件和时序，技能介绍卡的伤害和盾疗读取运行时同一套公式。逐项采用理由与实跑入口见各角色的决策输入和报告。[实施 #112](https://github.com/xOyMoveO/MYRIAD/issues/112) · [天刑](../../tools/balance/scenarios/roster-112-tianxing-decisions.json) · [素岚](../../tools/balance/scenarios/roster-112-sulan-decisions.json) · [焚诀](../../tools/balance/scenarios/roster-112-fenjue-decisions.json)

## 固定场景

| 角色 | 零预置与独立专项 |
| --- | --- |
| 天刑 | 同一目标从零有效普攻开始。引擎逐击记录漏击、第三击、相邻目标各自的溅射、换目标和超过四秒。单独以满恢复实际近战命中确认有效计数与伤害归属。 |
| 素岚 | 零预置不携带疾行刃或连风刃。独立对照自然移动和技能位移，按事件记录就绪、强化普攻及额外伤害。蓄势优势另列。 |
| 焚诀 | 初始无灼烧和既有火海。分别记录直接段、灼烧刷新前后的扣血刻、驻留与脱离火海的实际扣血。脉冲按照每秒一跳、最多四跳结算。 |

固定场景对每人八套 Lv20 构筑运行独自出手和队友先控，再分别记录常规输入延迟和零额外延迟。报告共 96 条零预置轨迹和 144 次同层配对。四项指标取 1.5 秒爆发、6 秒伤害、净行动损失及有效盾疗。每次同层比较冻结另外两层、共用 Q/W、初态及动作表，以临时停用该层的共同轨迹用于边际归因。次级弹道、空间碰撞及人可操作范围按报告中的覆盖缺口解释。[角色场景](../../tools/balance/scenarios/combos/)

另用同等级和同预算对比三人及朔、铆钉。Lv4、Lv12、Lv20 采用完全相同的阶段配点、满血落霞目标、起手距离和来伤。独立 Fabric 样本在三种阶段向角色注入相同顺序的物理、魔法和真实伤害，记录满血、每段实际扣血及余血。雷环生效后的非真伤减免单独复测，减伤归入承伤。

## 引擎专项的修正

- 素岚的突刺和跃进在最后一个动作刻结束时，运行时先清除移动状态，再调用被动。缓时下最后一段速度可能低于自然移动的最大采样值，原先会被计入疾行刃。两招结束时用实际位置重置被动采样锚点，保留正常移动进度。引导另核对常速十个行动刻和半速二十个真实刻。
- 焚天火海的定时损血允许同一真实刻被重复推进时再次结算。重复推进探针在第二跳复现两次实际掉血。火海按本次施法内的已结算序号去重，保留原真实刻、间隔与每跳数值。独立跃进样本曾因远端实体区块未就绪出现落地零伤。目标移入测试已加载的结构区块后按原断言验证主目标、驻留目标和脱离目标。

## 战场固定复跑

- 清线在 3:00、8:00 生成四名真实小兵。用当阶段预算、同一组购点、同阶 Q 与近战普攻重放。目标固定聚团，英雄脱离时按固定距离回位。该脚本下三名英雄仍明显慢于策划的清线参考。四人前组纯 Q／普攻也报出较慢结果，差异需结合实际线权、己方小兵贡献、技能组合和走位归因。
- 清营取单独的侦察机、重装步行机。实际打出技能、普攻和野怪还击，记录生命、尾刀、掉落及刷新。正式营地连刷、仇恨转移和多人配合列入整体复查。
- 3:00、10:00、18:00 从一波真实小兵进塔起分别记英雄和兵线伤害，在三档合成塔上复跑。正式樱隙前线使用外塔和高地塔，中塔样本用于统一对比。前一票与本票使用共同战场规则。跨阵容清线、清营速度和双人推进留给全阵容联校。

## 复跑

用 JDK 25 和已验证的共享资源目录。每个过滤器在独立 Fabric 服务端 JVM 串行运行，保留匹配、完成、实际 XML 和事件轨迹。

```sh
bash ./gradlew --offline build
python tools/fabric/prepare-ci-release.py
python tools/fabric/run-ci-gametests.py --offline \
  first_group wind_cast_animation fenjue_leap balance_tianxing balance_sulan_fenjue balance_haste \
  balance_roster_112_lane balance_roster_112_camps balance_roster_112_towers

python tools/balance/replay-roster-112.py \
  --baseline "$ROSTER_BASELINE" --release build/ci-release \
  --engine build/reports/fabric-ci --output build/balance/roster-112
```

`ROSTER_BASELINE` 指向 #111 的配对发行目录。需要在报告附原始聚合证据时，`--baseline-engine` 接收按过滤器子目录保存的日志及 XML。测试范围为服务端与合成场景，真人整局和正式地图仍由玩家另验。平衡数值差异只作提醒。
