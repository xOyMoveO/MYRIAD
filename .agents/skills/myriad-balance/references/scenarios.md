# 选择能回答问题的对照

| 玩家问题 | 固定条件 | 观察量 |
| --- | --- | --- |
| 一套技能能否收尾 | 双方等级与可花金币、实际购点、分支、朝向、距目标距离、起手资源 | 从第一次输入到命中逐刻记账，报告首套末和每次补 A 后的剩余生命 |
| 四项极值由哪种分支产生 | 零预置下的八套终局组合，另列绕背、叠层、靠墙或受击等专属前提 | 分别找 1.5 秒爆发、6 秒平均输出、6 秒有效盾疗与控制覆盖的极值，列出各自组合 |
| 支援或范围效果值多少 | 同一攻击序列、队友先控和地形，一次加入、一次移除待估技能 | 实际吸收、有效补血、净多出的命中或控制。1／2／3 名英雄分别报收益，再按条件命中率求期望 |
| 这套配点何时买得到 | 收入与购买的实际时刻、逐项报价、谁取得补刀／团队赏金 | 终点预算下的最优配点，以及沿时间轴能真正购得的点数、下一点缺金和买到的时间 |
| 5v5 是否发育过快 | 同一套英雄定义，分别取单人路、野区游走、双人路或支援位 | 0–28 分钟等级、购点、主动收入和灵脉份额。1v1／2v2 另查规则可用性 |

**同一场景复算。** 纯调参保留场景版本。机制改变使旧动作不再合法时，保留旧版本和失效原因，在新场景版本报告合法动作。独自出手与队友先控分别展示。目标先控产生的伤害机会只归因一次。

**寻找实际入口。** 正式工具和四角色原型有不同的覆盖范围。从当前检出查看 `build.gradle` 与 `tools/`。历史原型保存了固定快照、报告、引擎和客户端记录。复算时在原型提交的检出中运行，记录使用的提交与日期。[原型运行说明](https://github.com/xOyMoveO/MYRIAD/blob/b97a9e0348c9716ecca7eafa7d85f325a8109eb1/tools/balance-prototype/README.md)

**已有专项与实战。** 仓库根目录的 `python tools/fabric/run-ci-gametests.py --help` 给出可用过滤项。只有需要核对引擎语义时才运行相应项，核对匹配、完成标记和 XML 实际用例。真实 3v3 体验由人记录，把地图、兵线、目标初态以及观察者判断一起保存。
