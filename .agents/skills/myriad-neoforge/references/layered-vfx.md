# 万象技能特效：多层高清 2D、模型主体与像素修饰

适用于 MYRIAD 技能释放、飞行物、轨迹、命中、范围和持续特效的制作、接入与验收。项目路径相对当前仓库根目录；本轮只制作规范或素材时，不据此自动改造全部技能。

## 表现要求

- 以高清 2D 特效的多层叠加丰富表现。按各层职责组织轮廓、光效、纹理、轨迹和冲击，形成清楚的主体、空间层次与节奏，避免只换颜色或重复堆同一种粒子。
- 按角色和技能主题选择形状、材质、配色与运动方式；沿用项目包罗万象的方向。高清指在实际游戏视距下保持轮廓和细节清晰，不靠放大小图或模糊光团冒充细节。
- 2D 像素特效用于修饰，如火星、碎屑、短闪光、符号碎片和尾迹颗粒。保持清晰像素边缘，与高清主层共享配色、动势和时序；不把所有层统一降成粗像素，也不让修饰层抢走主体。

## 模型主体的使用边界

- **技能释放飞行物时，必须使用可辨识的三维模型作为飞行物主体**，再叠加高清 2D 光效、拖尾与 2D 像素修饰。飞剑、箭矢、弹丸、能量球和投掷物等均遵守此要求；不能以单张朝向相机的贴片、粒子团或纯拖尾替代模型主体。
- 优先复用与技能造型相符的现有模型；缺少合适主体时新增模型。模型可以简洁，但必须具有实际体积、清楚轮廓和符合技能的材质表现，不要求每个飞行物都重做一份资产。
- 非飞行物技能按需要增加模型，如召唤物、器械或实体化的场景主体；斩击弧、地面预警、冲击环等可由多层 2D 构成，不一律强制增加模型。
- 新建或调整 Blockbench 主体时，使用 [minecraft-ai-generate-bbmodel](../../minecraft-ai-generate-bbmodel/SKILL.md) 的结构化规格与生成流程。使用 ItemDisplay 承载模型时，按 [minecraft-itemdisplay-orientation](../../minecraft-itemdisplay-orientation/SKILL.md) 验证模型前向、三维朝向、缩放与曲线飞行，不能盲套历史模型轴向。

## 分层与时序

先按技能实际阶段列出需要的层及其职责，再制作资源。可从下列层中选择并组合，不机械要求所有技能都带齐全部效果：

| 阶段或职责 | 表现内容 |
|---|---|
| 起手、蓄力与预警 | 能量聚集、轮廓亮起、释放方向或范围提示；让玩家看清即将发生的动作 |
| 主体层 | 飞行物模型或技能核心形状，承担最容易辨识的轮廓与运动 |
| 高清 2D 主效果层 | 能量纹理、刃光、火焰、烟雾或冲击形状，增强材质、厚度和主题特征 |
| 辉光与边缘层 | 光晕、亮边和局部闪烁，突出主体轮廓；保持亮暗层次，避免叠成过曝白团 |
| 轨迹与空间层 | 连续拖尾、速度线、残影或环绕层，说明速度、方向与空间路径 |
| 命中与结束 | 命中闪光、冲击环、扩散或消散，和接触时刻、材质、结束原因对应 |
| 2D 像素修饰层 | 少量有节奏的火星、碎片和粒点，补充颗粒感与运动细节 |

- 每层明确尺寸、朝向、锚点、出现时刻、寿命、透明度、颜色与变化曲线。通过错峰出现、缩放、旋转、明暗和淡出形成节奏，而非所有层同时生成、静止叠放、同时消失。
- 2D 层按用途选择朝向相机、贴地或沿运动方向摆放；拖尾与模型共享实际轨迹，转弯、上升、俯冲时仍连续。模型主体应在不同视角可见，光效不得长期盖住其轮廓。
- 命中、未命中、打断、到达终点的结束表现按技能实际结果区分；预警和表现范围与已有服务端判定对应。本规范本身不授权修改伤害、碰撞、射程或施法时序。

## 资产与接入

- 用 [game-image-generation-rules](../../game-image-generation-rules/SKILL.md) 制作与检查贴图或序列帧；分别保留需要独立控制的主效果、辉光、拖尾、命中和像素修饰层，便于调整时序和叠加。
- 依据实际屏幕占用和近景观察选择贴图分辨率与序列帧密度，避免拉伸模糊或无收益的大图。透明图检查真实 alpha、边缘与黑白边；仅在现有材质明确支持时使用黑底加法混合。
- 多层接入时核对透明混合、遮挡、深度、贴地闪烁与叠加亮度。优先复用项目已有可用渲染路径，不因要求更丰富就预设新增整套渲染系统。
- 用有限寿命、数量、生成频率和可见距离控制开销；通过材质、形状与时序丰富表现。死亡、换角、退出、技能取消及对局重置时按既有生命周期清理关联对象。

## 验收与交付

- 在实际游戏尺度下检查主体轮廓、层次、配色与节奏；分别观察施放者、目标和侧面视角，确保看清方向、范围和命中反馈。
- 飞行物必须看见模型主体，并检查水平、上升、俯冲、转弯及命中时的朝向与拖尾。非飞行物检查所选 2D 层或模型是否符合其表现职责。
- 观察明暗背景和多个技能同时释放时的效果：主层清楚、像素修饰协调，没有过曝、边缘污染、明显断尾、闪烁或长时间遮挡视线；相关场景同时检查运行开销。
- 报告实际采用的模型、各层职责、资源位置及已完成的检查。区分素材检查、构建和客户端视觉验收；没有运行客户端时，明确标记视觉与性能待验收。
