# 樱隙前线平衡标杆原型

打开 [benchmark.html](benchmark.html) 就能比较落霞、夜影、刻衡和青萝。文件内含数据，下载后可离线使用。[本轮报告](REPORT.md) 给出主要读数。[标杆原型议题](https://github.com/xOyMoveO/MYRIAD/issues/96) 收集策划对实战的反馈。

## 重跑

在仓库根目录使用 Python 3.10 或更新版本，无需安装分析依赖。

```sh
python tools/balance-prototype/audit.py --as-of 2026-11-28
python tools/balance-prototype/audit.py --trace keheng ABB --scene 队友先控 --mode 当前 --level 20
```

第一条命令读取归档快照，输出 HTML、Markdown 和完整 JSON。第二条把所选分支 60 秒内的事件按真实刻写到标准输出。省略 `--as-of` 时按运行当天判断复审是否到期。`--exceptions` 可指定另一份 JSON 数组，文件缺省时使用空表。`--out` 可指定输出目录。

重新采集当前游戏规则和手改样例需要项目的 JDK 25、Gradle 与 Fabric 依赖。运行下列命令会使用该检出的独立测试世界。

```sh
python tools/balance-prototype/capture.py --offline
python tools/balance-prototype/audit.py --as-of 2026-11-28
```

采集器先构建当前 JAR，运行四角色专项和 3v3 外塔专项，随后将构建输入复制到临时目录，把刻衡「一秒之外」的持续时间从 60 刻改为 100 刻，再次构建与实际施放。设计例外文件只由离线报告读取。需要重跑真实客户端时，使用 Python 3.11+、桌面图形环境及项目已验证的 MCPFabric 26.3 测试模组。

```sh
python tools/balance-prototype/client_trial.py --bridge-jar /path/to/mcpfabric-0.10.0+26.3.jar
python tools/balance-prototype/audit.py --as-of 2026-11-28
```

客户端复用项目的合成世界种子和经过摘要校验的共享资源，在新目录加载手改 JAR。脚本在训练界面升至 Lv20、学习三阶「一秒之外」，按 R 并左键确定落点，读回法力、冷却并释放输入。R 的持续时间与脉冲次数另由独立服务端逐刻采集。两个 JAR、完整快照、日志和 XML 在本机 `build/balance-benchmark/`。复跑产生新制品时使用新摘要匹配对应客户端记录。

## 快照与覆盖

[samples/balance-snapshot.json](samples/balance-snapshot.json) 记录游戏基线、格式版本、地图和规则摘要。注册器列出全部 15 名角色、120 个候选技能，详细导出覆盖本轮 4 名角色的 32 个候选。输出包含实际绑定类、分阶蓝耗与冷却、伤害片段、盾疗系数、属性点增量、1–20 级生命与法力。尚未提供只读导出接口的兵线、工资、塔与穹层字段从对应 Java 声明读取，快照保留来源位置。两套 JAR 的字节摘要、快照摘要、刻衡场类字节及三阶施放过程见 [引擎证据](samples/engine-evidence.json)。[客户端记录](samples/client-trial.json) 与手改制品按 SHA-256 配对。

## 怎样读数字

| 分析 | 条件与结果的适用范围 |
|---|---|
| 静态预算 | 每人固定被动、E、R 各选一支，Q、W 共用。单段对目标的伤害除以同级参考脆皮生命的 1%，得到预算点。同一箭的不同穿透次序分别列出。技能的使用条件、目标类别和命中时序决定哪些段能一起发生。 |
| 经济 | 当前樱隙前线，对称双方，无追赶加成。首波按预设，假定生成 15 秒后补刀，三名队员轮流最后一击，队友共享经验。主人公在 0、3、7、12、16、20 分钟到泉水，前后各 12 秒拿不到兵。另一条路线轮流清霜兔与碧兽，逐营地检查可用时间，清营期间移除兵线收益。两条路线均无击杀、助攻、推塔或灵脉收入。 |
| 五属性最优 | 同线角色的 20 分钟收入决定终点预算。落霞的收益取 60 秒普通蓄力箭打零抗静止目标。夜影、刻衡取同窗口单独反复 Q 打 45 抗目标的伤害，青萝取 Q 对持续缺血盟友的治疗。其余目标为自身对物理或魔法伤害的有效生命。穷举整数点数，使这两项乘积最大，同时给出二者的帕累托前沿。回泉时在已买点数与终点点数之间择优加点，显示购买顺序与余金。 |
| 连招 | 沿用 20 分钟同线终点的可用金币。防守参考脆皮用相同预算尽量均匀购点，表内可查其余金。分别模拟经济实际可达的等级和强制 Lv12、Lv20。后两组用于在同经济下观察成型分支。攻方满蓝、全技能就绪，从第一次动作开始计时。6 秒输出按不封顶的累计伤害统计，首次跨过满血目标的时刻另记 TTK。 |
| 脚本 | 落霞依次尝试 Q、E、R，夜影为 R、E、Q，刻衡为 R、E、Q、W，青萝为 E、Q、R、W。按本支实际阶数检查冷却、法力、起手与后续动作占用，无法施放时普攻。接近两格、视线畅通、无穿透、无暴击。普攻用完整恢复或满拉，近战取期望段值。动作占用、近距离接触时点和目标反应为原型场景假设；6 秒的峰值仅覆盖所列脚本。 |
| 两个对手场景 | 独自出手时从正面开打，固定场内目标停留一秒。队友先控时允许夜影从背面开打，测试目标全程留场。各占一半为策划比较权重。队友控制本身不记为施术者收益。缓时叠加按最低行动倍率逐刻积分，禁锢仅在计划移动的刻数内记账。 |
| 支援与 A/B | 同一受援者从 55% 生命开始，在 6 秒内承受六次各为同阶段参考生命 9% 的原始来伤，依次为物、法、真、物、法、物。逐击扣减相关抗性、同源盾取强刷新，按到期时间依次耗盾，治疗受缺血量限制。盾疗有效生命列只计已消耗的盾或补血，按对应来伤倍率换回减伤前数值。A/B 比较以移除待比较一层的同脚本为共同基线，比较伤害、有效回复、实际吸收及独立反击者少完成的普通攻击。平均增量为正时给出相对差，以 8% 作为试测提示。 |
| 候选与提醒 | 候选防御每点 +15 双抗，冷却每点 +12.5 技能急速。夜影物理段可计入临时额外物攻，灵盾示范按额外物攻成长并保留第一笔主属性的盾量收益。参考线、当前构建和候选试算分别显示。刻衡的区间及过期日期是为演示复审而写的样例。 |

单目标伤害和资源的引擎对照覆盖选定的输入。完整 60 秒脚本、实图命中率、走位收益、多人治疗价值与六人局的经济分布仍需真人对照。策划可记录“符合”“偏高”“偏低”，附分支、时间或位置；只有试玩反复支持同一差异时，才有依据调整共同筛查线。
