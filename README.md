# 万象 · MYRIAD

万象是 Minecraft 的多题材角色团队对抗模组，原名《仙凡劫》。玩家组成两支队伍，选择角色、学习技能分支，通过兵线推进、野区争夺和团队配合，依次摧毁防御塔，最终击破敌方水晶。角色题材不限于修仙。

当前版本面向 **Minecraft 26.3 / Fabric / Java 25**，包含十五名可选角色、120 个候选技能，以及 3v3、5v5 两种对局模式。

## 玩法与角色

一局从分队和轮流选角开始。双方共享角色池，同一角色只能由一名玩家选择；全员选完后进入泉水，经过十秒准备再开战。玩家在对局中获得经验和金币，用技能点学习能力，用金币强化力量、智慧、速度、防御、急速五类属性并购买补给。力量每点增加 15 物攻，提升物理普攻和按力量成长的技能伤害。智慧每点增加 20 法强，提升法术普攻及使用法强的技能、治疗和护盾。墨尘、青萝和云笙的法术普攻每点智慧多打 10 点，寒泽多打 12 点，均为减伤前数值。

每名角色有八个候选：两个被动、两个常规技能、两个主要技能和两个终极技能。被动、主要、终极各选一个分支，两个常规技能可以同时学习。被动免费选择，在英雄 1、4、7、10、13 级达到一至五阶，晚选时直接获得对应阶数。每级的一点技能点供主动技能使用，大招在 4、8、12 级开放投点。**八个候选不代表八个技能同时可用。** 界枢中双击同一候选技能或属性图标即可确认，两次提交至少间隔一秒。具体效果、等级要求和消耗可在游戏内图鉴与技能面板查看。

| 模式 | 队伍规模 | 地图结构 |
| --- | --- | --- |
| 5v5 | 每方最多五人 | 三路兵线、分层防御塔、泉水、水晶及野区 |
| 3v3 | 每方最多三人 | 独立配置的单中路地图，保留塔序、水晶和野区目标 |

草丛与视野影响目标发现，双方也可争夺野怪和资源点。地图设施、兵线路径、草丛、营地和小地图边界均可配置，服主可以按地图安排战场。

十五名角色为：夜影、天刑、焚诀、墨尘、素岚、凌渊、寒泽、青萝、赤霄、云笙、朔、刻衡、伊珂、铆钉和落霞。例如：

| 角色 | 机制示例 |
| --- | --- |
| 居合·朔 | 在收鞘与出鞘状态间切换，用格挡反击、突进和延迟刀痕组织连招 |
| 时律·刻衡 | 布置局部缓时领域，减慢受支持目标的行动与独立弹体；技能冷却和效果到期仍按真实时间计算 |
| 虹轨·伊珂 | 在定轨炮台与游走阵列之间选择，手动瞄准并逐次开火 |
| 铆钉·战场筑垒师 | 在墙面部署战术锚点，配合牵引、队友护盾和撞墙控制作战 |

## 安装与版本要求

| 组件 | 当前要求 |
| --- | --- |
| Minecraft Java 版 | `26.3` |
| Fabric Loader | `0.20.1` |
| Fabric API | `0.166.2+26.3` |
| Java | 运行至少 `25`；开发构建使用 JDK 25 |
| 万象客户端 | 纯无手第一人称 `myriad-0.1.0-no-arms.jar` |

启用万象后，第一人称显示武器、持物和特效，关闭万象玩法后恢复原版手臂。九名近战角色的左右主手动作互为镜像。[近战普攻动作说明](docs/verification/melee-firstperson.md)

天刑采用右下竖直前指的纯无手第一人称待机姿态，连续挥剑时从上一刀的换侧守势接招，收剑沿画面下缘连续回位。[天刑实机说明](docs/verification/tianxing-sword-prototype.md)

客户端与服务端使用同一版本的万象和上表列出的 Fabric API，万象网络协议为 32。每个实例安装一份发行包。自行构建见[开发与构建](#开发与构建)。

1. 新建一个独立的 Minecraft 26.3 Fabric 实例；服务器也使用独立目录和新世界。
2. 将所选万象发行包和 Fabric API 放入相应实例的 `mods/`，确认没有重复的万象或旧仙凡劫 JAR。
3. 用该实例启动游戏或服务器。独立服务器首次启动需按 Minecraft 要求确认 EULA，再配置端口、白名单与管理员。
4. 进入新世界，按下一节启用玩法。仓库包含模组源码与运行资源，**不包含正式 3v3/5v5 地图存档或完整游戏实例**。

旧版本涉及内部身份及加载器迁移。先备份，勿用新包直接打开唯一一份旧世界，也不要把新旧模组装在同一个实例中。旧世界的处理见[地图与存档](#地图与存档)。

## 第一次游玩

### 进入大厅和训练场

服主先在测试世界执行 `/myriad mod on` 启用玩法。按 **H** 打开万象大厅，点击「进入训练场」即可前往同一服务器的独立训练世界。第一次进入时会布置近战练习区、带距离标记的射击道和位移障碍。未报名的玩家和正在排队的玩家都可以练习。

在训练菜单选择角色、创建人偶、恢复生命或刷新冷却，也可以单独启用无冷却等练习选项。训练场默认关闭玩家对战；双方都开启 PvP 后才能切磋。离场时清理练习角色和经济，返回大厅。排队中练习会保留顺位，锁定参赛名单后自动进入选角。

在“选项 → 控制 → 按键绑定”可以重绑大厅键和技能键。技能键默认未绑定。战斗面板在未绑定时标「槽1」至「槽4」，绑定后显示实际按键。按 `C` 打开个人信息和技能面板；在训练场可随时换角色试练。

在个人信息的属性页双击属性图标即可购买。五项各自从 360 金起价，同一属性每次涨价 20%，逐档四舍五入。开局 500 金，买一点后余 140 金。各项可持续购买，技能总冷却缩减上限为 60%。

技能、属性与补给页共用「界枢」面板。在技能页，将鼠标移入图标可查看用法、消耗和关键数值，移开即收起。十五位角色各有一幅技能介绍场景，同一角色的八个候选技能共用。放大 GUI 时，卡片优先为说明和关键限制留出空间。单击技能格选中，双击或按底部按钮学习、升级。未习得技能按一级预览，伤害按减伤前显示。

战斗面板默认在左下角，集中显示血量、护盾、法力、经验、四个主动技能和已选被动。可以在 `/myriad hud` 中整块移动、缩放或隐藏。个人战斗面板显示时，按 `T` 可在面板上方聊天，按 `/` 可输入命令。悬停玩家消息的时间可查看完整日期，以及记录的是发送时间还是接收时间。

看见 20 格内其他英雄的血条时，姓名上方会显示其眩晕、沉默和禁锢。图标边环在最后两秒缩短，距离太远或标牌互相遮挡时会收起。

补刀敌方小兵时，补刀者拿全额奖励，12 格内的存活队友各得 80% 基础经验。Tab 和赛后计分板显示击杀、死亡和助攻。小地图在固定裂隙蟹营地旁显示本方已知的刷新时间。

瞄到敌人的普通近战可以提前最多 2 刻按下，恢复完成时按当时准星出手。客户端启动参数 `-Dmyriad.meleeBufferTicks=0` 可单独关闭。落霞按住攻击键或使用键均可拉弓，达到蓄力门槛后松开先按的键放箭。准星指向可用的商人或训练假人时，使用键优先交互。上一箭射出后即可再次起弓。若客户端已消费近战缓冲而服务器还差一刻回满，服务器最多保留这一次输入至下一刻，再按当前准星、目标、距离和控制状态决定是否出手。

正式对局的逆风金币补偿比较双方在线参战者的人均本局累计金币，不受属性和补给消费影响；经验补偿仍按等级差计算。

练习场的假人可以用于比较技能伤害，练习不会占用主地图的正式场地。

选好角色和阵营后，可在训练或正式对战中长按鼠标中键打开团队信号轮盘，松开时向同阵营队友标记 18 格内的位置。正式对局阵亡后，按 `J` 或输入 `/myriad recap` 查看死亡回顾。

生命低于 25% 时，战斗面板边框提示残血。

### 有地图：组织一场对局

服主先配置相应模式的路线、塔、泉水和水晶，在对局空闲时用 `/myriad arena 3v3` 或 `/myriad arena 5v5` 选定地图。玩家从 H 大厅加入当前模式的队列，可关闭界面或浏览图鉴；需要离开队列时点「退出队列」。

1. **3v3** 满六人时，等待最久的六人进场。队中恰有两人或四人时，一人即可提议小规模对局。15 秒内名单不变，分别开 1v1 或 2v2。期间有人退队、断线或新入队，提议作废。**5v5** 满十人开局。
2. 系统随机分队。3v3 由守护方先选，六人局依次是蓝 1、红 2、蓝 2、红 1，每个名额 20 秒。5v5 沿用毁灭方先选及每手 30 秒。可以提前私下预选，轮到本人时再锁定；全场角色唯一。关闭选角后按 H 可返回。
3. 名单锁定后，掉线不暂停。超时先锁定仍可用的预选，否则服务器随机选定剩余角色。重连者接回自己的席位。全员锁定后在泉水准备 10 秒，开战发放一次 500 金。
4. 开战后前 90 秒内开始的掉线，按该席位连续离线超过 20 秒判定。在线人数较少方可在提示的 20 秒内按 H 发起无责重开，一人发起即通过。重连、首杀或拆塔会使原提议失效。少人方全离线或双方全离线时由服务器结束。
5. 结算后可以返回大厅，或点「再排一局」以个人身份加入队尾。正在候场的玩家保留位置。

### 常用操作

| 操作 | 默认键或入口 |
| --- | --- |
| 大厅、队列、重开选角面板 | `H` |
| 个人信息、技能学习、属性与补给 | `C` |
| 商店 | `P` 或 `/myriad shop` |
| 回城 | `B` |
| 技能键 | 默认未绑定，需在控制设置中指定 |
| 需要选点的技能 | 进入选点后，鼠标左键确认、右键取消 |
| HUD / 小地图位置 | `/myriad hud` / `/myriad minimap` |
| 当前对局状态 / 结算 | `/myriad status` / `/myriad results` |

按键可以重绑，角色的特殊输入以技能说明为准。若界面没有同步数据，先确认服务器也安装了匹配版本的万象，且玩法已开启。

## 地图与存档

可以在 [樱隙前线](maps/cherry-rift-frontline/)下载浮岛建筑地图，并查看[露天平地的测量口径](maps/cherry-rift-frontline/README.md#露天平地)。存档自带静态野怪模型和两座可设置重生点、恢复生命值的复活泉，可在 Minecraft 26.3 Fabric 单人世界中游览。

樱隙前线的[野怪试玩指引](maps/cherry-rift-frontline/README.md#野怪试玩)提供三成平地版的 13 个营地点位。六种可战斗野怪各有移动和攻击动作，服务器在攻击动作的命中标记处判定伤害。需要预览营地时，管理员可在主世界对局空闲期间执行 `/myriad train on`，再用 `/myriad mob preview` 提前刷新营地。

如果已有樱隙前线三成平地版存档，可用下方的配置和打包步骤制作对局副本。地图设一条中路、13 个野怪刷新点，每方各有一处泉水、两座防御塔和一座水晶。新版配置从正式开战计时，首波 0:35 在基地生成，裂隙蟹 4:00 首刷。已有副本可以单独补入节奏配置。[3v3 设施配置和打包步骤](maps/cherry-rift-frontline/3v3-flat/README.md)

地图由地形和点位配置共同组成，需要服主单独准备。管理员可在主世界、对局尚未开始时，用 `/myriad settings` 打开设置，再进入地图设施编辑器，在实际位置设置设施和边界。

两种模式保留独立的五份配置：

- `myriad_lane_layout.json`：兵线路径、塔、泉水与水晶。
- `myriad_brush_zones.json`：草丛范围。
- `myriad_monster_spawns.json`：野怪与首领营地。
- `myriad_vein_spawns.json`：资源点候选。
- `myriad_minimap.json`：小地图边界。

5v5 配置位于世界根目录；3v3 位于 `myriad_arenas/3v3/`。`myriad_lobby.json` 为两模式共享大厅，`myriad_arena_selection.json` 保存模式选择。3v3 锁定参赛名单前会校验并加载同一份场地配置。编辑保存失败时仍沿用上次成功的数据。水晶地图以摧毁水晶决胜，无水晶地图可在设置中调整对局时限。

沿用旧地图时，在备份副本中导入地图配置，按配置重建新设施，并核对地形和通行空间。**不支持导入 NeoForge 旧玩家等级、金币、角色、技能、旧个人 HUD 或旧 `myriad_match.json` 检查点**，也不要通过旧实体继续旧局。Fabric 玩家状态、个人 HUD 与对局使用独立数据。

从本版进入玩法时，角色的原版物品、经验、效果和游戏模式随玩家存档保存。正常重启独立服后仍可在关闭玩法时归还，重复关闭不会再次清理玩家。旧版本未保存的原版物品需从原备份找回。

独立服务器保留新版本的对局检查点恢复功能；单人/LAN 世界由主持人保存退出后结束本局，重新打开不会续局。需要回退时，恢复匹配的加载器、模组、世界和配置整份备份。

## 开发与构建

使用 JDK 25，在仓库根目录执行。Gradle Wrapper 已固定为 9.7.0，Loom 为 1.18.4；版本声明见 [gradle.properties](gradle.properties) 与 [build.gradle](build.gradle)。

macOS / Linux：

```sh
java -version
bash ./gradlew build
```

Windows PowerShell：

```powershell
java -version
.\gradlew.bat build
```

首次构建需要联网获取依赖。本分支的客户端发行包输出为 `build/libs/myriad-0.1.0-no-arms.jar`。

开发运行入口：

| 用途 | macOS / Linux | Windows PowerShell |
| --- | --- | --- |
| 启动客户端 | `bash ./gradlew runClient` | `.\gradlew.bat runClient` |
| 启动独立服务器 | `bash ./gradlew runServer` | `.\gradlew.bat runServer` |

开发客户端和服务器分别使用项目目录下的 `run-fabric-client/`、`run-fabric-server/`。服务端仍需确认 EULA 并配置端口、白名单与管理员。

[GitHub Build](.github/workflows/build.yml) 在 push 和 pull request 时使用 JDK 25 执行构建，不自动运行游戏内测试、上传 JAR 附件或创建 Release。
